# Ember Atlas dataset

This folder is the single location for every scientific file Ember Atlas uses. Its machine-readable catalogue is
[`metadata/manifest.json`](metadata/manifest.json). For each file, the manifest records:

- path and processing stage;
- investigation and format;
- SHA-256 and size;
- whether the file is committed;
- upstream source and intended use.

It also records the expected record counts. Run `python scripts/validate_dataset.py` to check that the files on disk match the manifest.

## Sources and investigations

The data comes from the NASA Physical Sciences Informatics (PSI) repository. Each investigation's catalog record
declares **CC0-1.0**. The eight experimental files below are byte-identical (SHA-256) to official NASA downloads; the official URLs are listed in
`references/nasa-psi/official_file_manifest.json`.

| Folder | Investigation | NASA id | DOI | Files |
|---|---|---|---|---|
| `raw/flex/` | Flame Extinguishment Experiment (FLEX) | PSI-69 | [10.60555/mbq8-0451](https://doi.org/10.60555/mbq8-0451) | `FLEX.csv` (274 rows), `info.md` |
| `raw/cfi/` | Cool Flames Investigation (CFI) | PSI-39 | [10.60555/m6pj-a914](https://doi.org/10.60555/m6pj-a914) | `CFI.csv` (87 rows; 8 exact repeats retained), `info.md`, `layout.json` |
| `raw/same-r/` | Smoke Aerosol Measurement Experiment Reflight (SAME-R) | PSI-101 | [10.60555/2np7-jv14](https://doi.org/10.60555/2np7-jv14) | `SAME-R.csv` (109 rows), `info.md`, `layout.json` |
| `raw/spice/` | Smoke Point In Co-flow Experiment (SPICE) | PSI-107 | [10.60555/9kbh-e962](https://doi.org/10.60555/9kbh-e962) | `Spice.csv` (469 rows; 34 exact repeats retained), `SmokePointReview-0g-3.xlsx`, `Spice Flight Test Data II modified.xls`, `Spice_Flight_Flamelength.xls`, `info.md`, `layout.json` |
| `raw/bass-ii/` | Burning and Suppression of Solids II (BASS-II) | PSI-25 | [10.60555/4qc4-de67](https://doi.org/10.60555/4qc4-de67) | `BASS-II.csv` (129 rows; UTF-8 BOM header preserved), `info.md` |

Original file names and bytes are kept unchanged.

`info.md` and `layout.json` are NASA catalog summaries as packaged by the open-source Fotia project. Fotia's MIT licence is in
`upstream/FOTIA_LICENSE`. These summaries are hashed curation inputs, but unlike the data files they are not byte-verified against NASA.

Repeated rows are never removed. Missing, zero, dash, "not applicable" and disputed values stay distinct.

## Layout

```
dataset/
├── raw/<investigation>/      original NASA files (never modified; hashes checked before and after every build)
├── processed/                curated release p0_v1_review, generated by curation/ (loaded into PostgreSQL)
├── metadata/                 manifest.json · baseline.json (pinned hashes) · data_dictionary.md
├── references/
│   ├── nasa-psi/             NASA catalog snapshots (psi*_catalog.json), acquisition manifests, NTRS metadata,
│   │                         restored report PDFs/DOCX (not committed)
│   ├── partial-gravity/      retrieval manifest for LUCI, Konno et al., Gollner et al., ACME (PDFs not committed)
│   └── findings/             AI-assisted candidate findings (pending human review)
└── upstream/FOTIA_LICENSE    licence of the upstream packaging of the raw files
```

## Processed data

`curation/pipeline.py` produces `processed/`:

| Files | Contents |
|---|---|
| `source_records.jsonl` | All 1,068 CSV rows with positional values, source identifiers as text, line ranges and duplicate pointers |
| `observations.jsonl` | Every CSV cell, with original heading and value, missingness, uncertainty status and any documented unit conversion |
| `spice/*` | All 19,641 populated workbook cells, workbook records and observations, and 2,960 reconciliation candidates (never merges). Also 1,311 media references, flame-length checks and calibration comparisons |
| `quality_issues.jsonl` | 363 open or documented issues with exact locations |
| `review/*` | NASA registry, findings, evidence snapshots, licences and publication rights |
| `audits/`, `data_dictionary.json`, `summary.json`, `REPORT.md`, `source_manifest.json`, `build_manifest.json` | Audits, data dictionary, summary, report and manifests |

Normalization never overwrites an original value. Converted values sit next to the original, with the rule and evidence
for the conversion. For example, the FLEX burning-rate unit mm²/s is documented from NASA/TP-2015-216046, Appendix A.1,
Table IX. Workbook formulas are recorded but never executed.

Every record keeps its provenance identifier, `dataset/raw/<investigation>/<file>::<sheet|CSV>::<row>`. That identifier
travels unchanged into the database, the API and the dashboard's source panel, so each chart point and citation leads
back to an exact file, row and column.

## Reference documents (restore before building the database)

The following files are cited but **not committed**, because their redistribution rights are not established:

- NASA report PDFs and DOCX guides;
- the SPICE thesis (University of Maryland);
- two supplementary workbooks;
- two NASA web assets;
- the partial-gravity PDFs, including an Elsevier author manuscript.

The curation review step and the database ingestion verify their SHA-256 hashes. Restore them once with:

```bash
python scripts/restore_references.py --download      # official URLs from the committed manifests; writes only on hash match
python scripts/restore_references.py --list          # names, SHA-256 and URLs
```

One page shell, `references/nasa-psi/psi107.html` (954 bytes), is committed. NASA's server inserts a per-request nonce, so it can never be re-downloaded byte-identically.

## Rebuilding and importing

```bash
python scripts/build_dataset.py      # raw → processed, re-pin metadata/baseline.json, rewrite metadata/manifest.json
python scripts/validate_dataset.py   # files, hashes, baseline and record counts
python scripts/init_database.py      # migrations + hash-verified ingestion + database record counts
```

A rebuild changes `build_manifest.json` (it records a timestamp) and therefore the pinned release ID. Ingestion never
overwrites a loaded release, so load a rebuilt release into a fresh database.
